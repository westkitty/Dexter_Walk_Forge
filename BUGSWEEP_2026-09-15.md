## Defect ledger

### BSW-01 — CRITICAL — Pages build corrupted the primary inline script

**Evidence:** The hosted build showed large sections of Dexter Walk Forge JavaScript rendered as visible page text. The Pages builder used `String.replace('</body>', ...)`, which targets the first matching closing tag. `index.html` legitimately contains a generated Walk Capsule HTML template with its own `</body>` before the real outer document close. The PWA hook was therefore injected inside the main inline script's template string. Its literal `</script>` closed the real script early and exposed the remainder as text.

**Fix:** Added `scripts/html-document.mjs`, which locates verified outer document boundaries and injects the body hook immediately before the final outer `</body>`. The build no longer uses first-match replacement for document injection.

**Regression guard:** `pwa-verify.mjs` now recreates the exact nested-HTML trap and asserts the first inline script is unchanged and executable. The built `_site/index.html` must preserve the source inline script byte-for-byte and place the PWA hook directly at the outer body boundary.

**Result:** FIXED AND VERIFIED.

### BSW-02 — HIGH — Service worker could delete caches belonging to sibling GitHub Pages apps

**Evidence:** Activation deleted every cache key except the active Dexter Walk Forge key. Cache Storage is origin-wide, while multiple project Pages sites can share `westkitty.github.io`.

**Fix:** Added a Dexter-specific cache prefix and cleanup now deletes only old keys beginning with that prefix.

**Result:** FIXED AND VERIFIED.

### BSW-03 — HIGH — Static PWA assets could remain stale indefinitely

**Evidence:** Non-navigation requests used cache-first behavior with no background refresh. If application assets changed without a service-worker byte change, previously cached Timeforge/PWA resources could remain stale.

**Fix:** Static requests now use cache-first plus background network refresh inside the app-owned cache. Navigation remains network-first with offline fallback.

**Result:** FIXED AND VERIFIED.

### BSW-04 — MEDIUM — Install affordance could overlap mobile capture/navigation controls

**Fix:** The install control now respects the existing DWF mobile/desktop bottom UI clearances and safe-area inset.

**Result:** FIXED AND STATICALLY VERIFIED.

### BSW-05 — MEDIUM — iPhone/iPad had no discoverable install path

**Fix:** iOS devices now receive an `ADD TO HOME` affordance with Safari Add to Home Screen guidance when not already standalone.

**Result:** IMPLEMENTED; real-device confirmation remains pending.

### BSW-06 — HIGH — PWA verification proved hook presence but not parser integrity

**Evidence:** The prior verifier passed the broken build because it checked only that manifest and install-hook strings existed.

**Fix:** Verification now checks parser-safe synthetic injection, exact built inline-script preservation, inline-script compilation, outer-boundary placement, app-scoped cache cleanup, and the prior manifest/icon/workflow checks.

**Result:** FIXED AND VERIFIED.
